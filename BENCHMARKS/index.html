    Benchmarks¶

    Machine: 8 vCPU Linux box, no GPU, Python 3.13. Measured on 2026-10-12. Token counts are chars / 4.

    Head-to-head with rtk (bench/vs_rtk.py)¶

    gh release download -R rtk-ai/rtk -p 'rtk-x86_64-unknown-linux-musl.tar.gz' && tar xzf rtk-*.tar.gz
git clone --depth 1 https://github.com/django/django /tmp/djb
git clone --depth 80 https://github.com/psf/requests /tmp/req
python bench/vs_rtk.py --rtk ./rtk --django /tmp/djb --history /tmp/req --json bench/vs_rtk_results.json
python bench/plot_vs_rtk.py

    The script builds scratch repos: a Django clone with 5 edited files, 3 untracked and 1 deleted; a pytest project with 4 failing tests out of 125; and a Rust crate with 2 failing tests out of 42. It runs each command once and feeds the same raw output to keelyard, while rtk runs the command itself. FORCE_COLOR is removed and NO_COLOR=1 is set for all runs. "Facts" are extracted from the raw output with fixed rules (see facts_* in the script) and count as kept when every part appears verbatim in the filtered text.

    command facts raw tok keelyard tok keelyard kept rtk tok rtk kept
    git status 9 161 61 100% 58 100%
    git log -n 40 (requests) 40 6,807 950 100% 2,378 100%
    git diff 91 1,653 1,064 100% 1,557 100%
    grep -rn (django) 15 277 230 100% 277 100%
    find *.py (admin) 30 299 136 100% 113 100%
    ruff check (django/utils) 307 43,582 3,022 100% 1,050 24%
    pytest -v (4 failing of 125) 7 3,289 312 100% 195 71%
    cargo test (2 failing of 42) 6 454 126 100% 119 100%
    total 56,522 5,901 5,747

    Caveats: one run per command, eight commands, fact rules written by us. rtk drops line numbers from ruff results and some assertion lines from pytest, which is why its retention is lower on those two. rtk handles many more tools.

    All 12 FAILED/assert/KeyError lines of the failing pytest log survive compression. The corpus is small. Please contribute more real logs.

    Swarm with a small local model¶

    These are real calls to qwen2.5-coder-1.5b-instruct (Q4_K_M GGUF) served by Ollama on CPU, with concurrency 4. There were 12 tasks against this repo: 8 Q&A or summaries, 2 patch drafts and 2 greps.

    • Wall time: 4 min 15 s; helper tokens: 14,452 in, 1,409 out.
    • Verified: 3/12. Both greps are local and need no model. One patch passed git apply --check; the other did not apply.
    • Q&A: 0/8 answers contained a valid path:line citation, and the verifier marked all 8 UNVERIFIED. A second run with a format example in the prompt also verified 0/8. One answer copied the example's file name, so the example was removed again.

    Conclusion: the verification layer does its job, but a 1.5B model is not a useful helper. Use a 7B+ local model or a hosted cheap model. We have not yet measured how well larger models verify.

    Swarm quality¶

    python bench/swarm_quality.py --runs 2, local qwen-coder 1.5B on Ollama, 2026-10-12. Five one-function bug fixes and five "which line does X" questions, in a repo where each file also carries 25 unrelated helpers. Single is the old swarm: whole file, one sample, diff output, git apply --check only. Pipeline is the new one: context pack, one-definition rewrite, tests on a copy, best-of-3, one retry with feedback, no escalation (no strong model configured). Ground truth for fixes is that module's own tests passing with the patch; for questions, citing the expected line.

    single, run 1 / 2 pipeline, run 1 / 2
    fixes actually correct 0 / 0 of 5 4 / 4 of 5
    fixes marked verified but wrong 3 / 2 0 / 0
    questions citing the right line 1 / 1 of 5 2 / 3 of 5
    questions marked verified 1 / 1 5 / 5
    model calls 10 / 10 33 / 39
    input tokens 12,435 / 12,435 5,034 / 6,309
    output tokens 1,679 / 1,712 2,835 / 3,626

    Checking patches against tests removed every false "verified" fix, and the rewrite format plus retries took a 1.5B model from 0 to 4 correct fixes out of 5. Context packs used about half the input tokens despite 3-4x more calls. What it does not show: a "verified" answer to a question means its citations exist, not that it is right (5 verified, 2-3 right). Ten tasks on one tiny model is a smoke test, not a benchmark; escalation and 7B+ models are not measured here.

    Cooperative swarm vs the best local setup¶

    Same 10 tasks (5 bug fixes, 5 questions), qwen-coder-1.5b on Ollama, 2 runs each. python bench/swarm_quality.py.

    mode correct of 20 (2 runs × 10) tokens tokens per correct wrong patches marked verified
    single 2 27,394 13,697 5
    pipeline 15 19,073 1,272 0
    best-local 18 28,081 1,560 0
    coop-nocritic 15 19,686 1,312 0
    coop 15 44,149 2,943 0
    • best-local is the same model with more samples and retries (best_of 5, retries 2). It stands in for "one strong agent" because no stronger model or API key was available. That comparison is still open.
    • coop adds the critic. It doubled the tokens and did not improve quality, so critic is off by default.
    • coop-nocritic (blackboard, voting, budget) costs about the same as the pipeline per correct answer. With one model the ladder had one step, so routing was not exercised here (it is covered by tests).

    keelyard's own overhead¶

    python bench/overhead.py counts what keelyard adds to every session (characters / 4 of compact JSON or text):

    item tokens
    MCP tool schemas, 13 core tools (default) 1,582
    MCP tool schemas, all 22 tools ([mcp] tools = "all") 2,401
    MCP server instructions 77
    CLAUDE.md / AGENTS.md guide block 144
    session brief, fresh project (cap 600) 74
    total per session, fresh project 1,877
    workflow guide, only when asked (plan / debug / review) 240 / 181 / 182

    Prompt recall adds at most 250 tokens per prompt and only when past sessions match; hints are capped at 12 per session.

    Net: the 8 filtered commands above saved 50,621 tokens, so one session that runs them nets 48,744 tokens. At the median saving per command, the fixed overhead is repaid after 4 filtered commands. A session that never runs a noisy command pays the 1,877 tokens and saves nothing; these are per-command measurements, not totals from real sessions.
